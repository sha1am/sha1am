## Backend Systems Portfolio

```go
package main

type Engineer struct {
	Name      string
	Role      string
	Company   string
	Strengths []string
}

func main() {
	me := Engineer{
		Name:    "Shadab Alam",
		Role:    "Backend Engineer",
		Company: "Trademo",
		Strengths: []string{
			"REST & microservice APIs",
			"event-driven pipelines with Kafka",
			"relational + search data modelling",
			"containerised delivery on AWS",
			"performance and reliability work",
		},
	}

	println(me.Name, "builds", me.Role+" systems.")
}
```

I build backend services in **Go** and **Python** — API layers, ingestion pipelines, and the data plumbing behind them. Day to day that means Django and Go services talking over Kafka, backed by PostgreSQL, Redis and Elasticsearch, shipped in Docker on Kubernetes. My direction is systems engineering: concurrency, latency budgets, and what happens when a dependency falls over.

| Focus | What I Work On |
|---|---|
| Service APIs | REST and microservice design, auth, validation, versioning, clean error contracts |
| Data pipelines | Kafka producers/consumers, batch + streaming ingestion, idempotent processing |
| Storage & search | PostgreSQL, MySQL, Redis caching, Elasticsearch indexing and query tuning |
| Delivery | Docker, Kubernetes, AWS, shell tooling, CI-driven deploys |
| Systems interest | Go concurrency, C++/Rust fundamentals, profiling and latency work |

## Current Direction

```text
Backend services in Go and Python
-> event-driven pipelines with Kafka
-> query and index tuning across Postgres and Elasticsearch
-> latency budgets, profiling, and load testing
-> deeper systems work: concurrency primitives, memory, networking
-> SDE-2 scope: design reviews, ownership, and on-call reliability
```

I care about the reasoning behind backend decisions: when a cache is a lie, why idempotency saves you at 3 a.m., what an index actually costs on write, and how a service should behave when its dependency is already down.
